-------------------------------------------------------------------------------
A) Wo wird geschrieben?
-------------------------------------------------------------------------------

Rohwert-Schreiben gibt es genau einmal:

  persistence.js:86   localStorage.setItem(key, value)   in save(key, value) -> boolean

Alles andere geht durch save/saveJSON/remove. save() faengt die Ausnahme und
liefert false; saveJSON() meldet ueber Events.DOCUMENT_SAVE_FAILED (B46).

Schluessel (STORAGE_KEYS): settings, draft, geoapifyKey, letzter Stand u. a.
Entwurf: `din_draft_current` (versionslos, Feldobjekt).
Einstellungen: `din_settings`.

Binaerdaten liegen NICHT im localStorage, sondern in IndexedDB:

  binary-storage.js    openDB / saveBlob / loadBlob / deleteBlob
  genutzt von          signature.js (Signaturbild), font-feature.js (Schriftdatei)

IndexedDB-Fehler, die im Code behandelt werden:
  - open fehlgeschlagen   -> reject(Error)              (Zeile 50)
  - open blockiert        -> reject('anderer Tab haelt die alte Version') (51)
  - devicememory/Quota    -> ?
  - onversionchange       -> db.close(), dbPromise = null

-------------------------------------------------------------------------------
B) Wer schreibt wann?
-------------------------------------------------------------------------------

draft-manager.js
  saveDraft()           collectDraft -> saveJSON; Undo-Stack; Caret merken
  scheduleAutoSave()    Debounce; Timer in `this.debounceTimer`
  flushPendingSave()    sofort schreiben (Lifecycle)
  #initLifecycleFlush() beforeunload / visibilitychange?
  loadDraft()           Entwurf lesen und anwenden (auch bei Multi-Tab)
  undo() / redo()       #applyHistoryState -> #restoreState + saveJSON
  resetDraft()          Felder leeren, Datum zuruecksetzen

Undo/Redo liegt AUSSCHLIESSLICH im RAM:
  #undoStack = []  ·  HISTORY_MAX_ITEMS (core.js Constants)

Multi-Tab (bewusst, kommentiert in draft-manager.js:110-114):
  - aktiver Tab gewinnt, "letzter Schreiber gewinnt"
  - Hintergrund-Tab ohne ungespeicherte Eingaben laedt den fremden Stand
  - sonst nur ein Toast (Constants.TOASTS.DRAFT.MULTI_TAB)
  - kein Web-Locks, kein Merge, kein Konflikt-Erkennen

C) Event-Bus (core.js, 275 Zeilen; Bus-Anteil ~60)
-------------------------------------------------------------------------------

createEventBus(target = new EventTarget())
  publish(topic, payload)     dispatchet CustomEvent, synchron
  subscribe(topic, handler, {signal}) -> unsubscribe-Funktion

Gemessen 2026-11-13 im laufenden Browser:

  bus.subscribe('dinbrief:test', () => { throw new Error('kaputt') });
  bus.subscribe('dinbrief:test', () => { gesehen.push('zwei') });
  bus.publish('dinbrief:test', {});
  -> gesehen = ["eins","zwei"], publish warf NICHT

  Also: EventTarget isoliert werfende Listener (Fehler landet als uncaught
  error in der Konsole), nachfolgende Subscriber laufen weiter. Der Publisher
  merkt nichts.

  ABER: publish() wirft synchron TypeError, wenn das Topic nicht mit
  `dinbrief:` beginnt. Ein Tippfehler im Topic bricht also den Aufrufer ab —
  mitten im Boot-Pfad oder im Save-Pfad.

Subscriber, die heute direkt am Speicher haengen:
  DOCUMENT_SAVE_REQUESTED, DOCUMENT_SAVED, DOCUMENT_SAVE_FAILED,
  DOCUMENT_CHANGED, NOTIFICATION_REQUESTED.

Lebenszyklus: subscribe() gibt eine Abmelde-Funktion zurueck; genutzt wird sie
in `destroy()` (draft-manager). Wer sie ignoriert, laesst Listener stehen —
besonders relevant, wenn Module neu instanziiert werden (Tests, Undo-Reset,
Theme-Wechsel mit View Transition).

-------------------------------------------------------------------------------
G) Entschieden am 2026-11-13 (bitte nicht erneut aufbringen)
-------------------------------------------------------------------------------

Nach dem Review zu B13. Jede Entscheidung steht auch im Code bzw. im
DECISION-LOG, damit sie nicht nur im Chat existiert.

1. UNDO/REDO BLEIBT NUR IM RAM.
   Der letzte Stand ist durch saveDraft() gesichert; Undo ueber einen Reload
   waere ein neues Feature. Kosten eines Rings: zusaetzliche Schreibvorgaenge,
   Quota, Multi-Tab-Kohaerenz. Wer es einbaut, muss alle drei mitloesen.
   Ort: draft-manager.js, Kommentar bei #undoStack.

2. LADEFEHLER VON SIGNATUR/SCHRIFT BLEIBEN STILL.
   Beide sind optional, und der wahrscheinlichste Fall (IndexedDB von einem
   anderen Tab blockiert) bietet dem Nutzer beim Oeffnen keine Handlung an.
   Speichern ist die Gegenrichtung: dort ist der Toast Pflicht und vorhanden.
   Ort: signature.js und font-feature.js, Kommentar am loadBlob.

3. EVENT-BUS WIRFT WEITER BEI FALSCHEM TOPIC.
   Der Vorschlag "console.warn statt throw" wurde abgelehnt: test/all.js:2014
   prueft den TypeError fuer publish UND subscribe. Der Guard ist Absicht —
   ein Tippfehler soll laut knallen, nicht still verschluckt werden.

4. BEHOBEN: IMPORT IST ATOMAR.
   Vorher: Entwurf geschrieben, dann Einstellungen; bei Quota im zweiten
   Schritt blieb ein Mischzustand. Jetzt werden beide alten Rohwerte vorher
   gelesen und bei Fehler zurueckgeschrieben (auch im catch). Test: setItem
   wirft fuer din_settings, Entwurf bleibt unveraendert.

5. KORRIGIERT: SIGNATUR-FOUC-BEGRUENDUNG.
   Die Review-Begruendung "Platz reserviert, Container sichtbar" war falsch:
   das CSS schliesst den data:image/svg-Platzhalter aus, der Container ist
   anfangs display:none. Die Entscheidung "akzeptieren" bleibt richtig, weil
   der Container absolut positioniert ist und das Blatt nicht verschiebt.

6. NICHT OBSERVIERBAR (kein Bug): "kurzes falsches Gespeichert" beim Undo.
   #restoreState setzt den Status, #applyHistoryState prueft und korrigiert —
   beides im selben Task, dazwischen liegt kein Paint.
