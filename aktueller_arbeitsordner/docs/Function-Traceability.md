# Function Traceability Matrix

Die Function Traceability Matrix ist das Herzstück unseres Compliance-Systems. Sie beweist, dass jede Zeile Logik in `website/` durch eine Spezifikation oder Architektur-Entscheidung legitimiert ist.

## 📖 Wie man dieses Dokument liest
Dieses Dokument aggregiert die bidirektionalen Verbindungen zwischen Code und Dokumentation.
- **Funktion / Modul:** Der funktionale Name der Logik (oft abgeleitet vom Dateinamen).
- **Code Datei:** Die physische Datei im Dateisystem (`website/`).
- **Architektur-Record (ADR):** Die Architektur-Entscheidung, die begründet, *warum* der Code existiert und *wie* er sich in das Gesamtsystem einfügt.
- **Implementierungs-Guide:** Die konkrete Anleitung, *wie* der Code zu schreiben und zu warten ist (Best Practices).

## 🤖 Automatisierte Mapping-Tabelle

> [!WARNING]
> **Manuelle Eingriffe verboten!**
> Die Tabelle innerhalb der HTML-Kommentare unten wird zu 100% maschinell erzeugt. Bitte trage hier keine neuen Zeilen manuell ein, da sie beim nächsten Build überschrieben werden.

Das Skript `tools/build_db.js` liest die `@adr`- und `@guide`-Tags aus den Quellcode-Dateien (`website/`) aus und generiert diese Tabelle beim Build-Prozess (`start.ps1`) neu.

Um einen neuen Knotenpunkt hinzuzufügen:
1. Schreibe die neue Code-Datei.
2. Füge den Header-Kommentar `/* @adr [[ADR-Name]] */` in die Code-Datei ein.
3. Führe `start.ps1` aus.

## 📝 Manuelle Notizen & Ausnahmen

Alles außerhalb der obigen HTML-Kommentare ist für **manuelle Notizen** vorgesehen. Hier können wir Architekturausnahmen, Besonderheiten oder Legacy-Vermerke dokumentieren, die das Skript nicht greifen kann.

### Bekannte Ausnahmen
- `website/css/reset.css`: Nutzt das globale CSS-Reset-Framework, welches historisch gewachsen ist und keiner spezifischen ADR-Verknüpfung bedarf. Das Reset ändert sich nie.
- `website/css/variables.css`: Deklariert lediglich die Basis-Tokens. Die echte Architektur-Entscheidung liegt bei den nutzenden CSS-Dateien (z.B. `layout.css`).
